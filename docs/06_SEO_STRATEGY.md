# 06 — SEO Strategy

SEO is a first-class requirement. This document covers technical SEO (rendering, URLs, metadata, structured data, crawl control), content SEO (keyword architecture, landing pages, internal linking) and commerce SEO (Merchant Center, feeds, reviews).

Principle: **every indexable URL must be genuinely useful on its own.** No doorway pages, no auto-generated thin facet pages, no spun copy.

---

## 1. Technical SEO

### 1.1 Rendering and crawlability

| Requirement | Implementation |
|---|---|
| Server-side rendered HTML for all indexable pages | Next.js App Router Server Components; static/ISR for catalogue and content (`03_TECHNICAL_ARCHITECTURE.md §4`). Product grids, prices, descriptions, reviews, breadcrumbs all in initial HTML. |
| Static generation where appropriate | Categories, collections, PDPs, journal, guides, policies are prerendered (`generateStaticParams` for the top N, ISR on demand for the rest). |
| No client-only content for crawlers | Filters update the URL and re-render on the server. "Load more" appends server-rendered HTML and updates `?page=`. |
| Fast TTFB | CDN-cached ISR pages; `12_PERFORMANCE_REQUIREMENTS.md`. |
| Clean HTML semantics | One `<h1>` per page, heading hierarchy, `<nav aria-label>`, `<main>`, `<article>` for content. |

### 1.2 URL and canonical rules

See `04_INFORMATION_ARCHITECTURE.md §1`. Summary:

- Canonical always absolute, HTTPS, chosen host, trailing slash.
- PLP with filters or sort: `robots: noindex, follow` with a **self-referencing** canonical. We deliberately do **not** combine `noindex` with a canonical pointing at the base page: Google treats that as conflicting signals and may ignore both. Link equity still flows through `follow`; facet links in HTML carry `rel="nofollow"` to limit crawl waste.
- PLP with `?page=N` (no filters): self-canonical, indexable. `?page=1` 301s to the base URL. No `rel=prev/next` (not used by Google), but previous/next links are plain `<a>` in HTML and the "Load more" control is a real `<a href="?page=N+1">` enhanced by JavaScript.
- Search: `noindex, follow`.
- Cart, checkout, account, admin, wishlist, track-order: `noindex, nofollow` + disallowed in robots.
- Products: canonical `/products/{slug}/`. Size/length selection uses `?variant=sku` (self-canonical to the base URL, not blocked in robots so Google can read the canonical). See §1.10 for how colour/finish is modelled so searchable variants get their own URLs.
- Products that are **out of stock stay live and indexable** with `availability: OutOfStock`, a notify-me form and alternatives. Only archived products leave the index (301 to a replacement or category chosen by the admin, else 410).
- Collections with fewer than 3 visible products are automatically `noindex` and excluded from the sitemap to avoid soft-404s and thin pages.
- Journal category pages: indexable.
- Tag pages: do not exist.

### 1.3 Metadata

Generated by `modules/seo/metadata.ts` via `generateMetadata`:

| Page | Title pattern (≤ 60 chars) | Description source |
|---|---|---|
| Home | `Kesa Lifestyle \| {tagline}` | Global default |
| Gender landing | `Women's Jewellery Online \| Kesa Lifestyle` | Category intro |
| Category | `{Category} for Women – Buy Online \| Kesa` (admin override) | Category SEO description → intro excerpt |
| Collection | `{Collection name} \| Kesa Lifestyle` | SEO description → intro |
| PDP | `{Product name} \| Kesa Lifestyle` (admin override; auto-append material if short) | SEO description → short description |
| Journal | `{Title} \| Kesa Journal` | Excerpt |
| Guides | `{Title} \| Kesa Style Guides` | Intro |
| Paginated PLP | `… – Page {n}` | Same |

Also emitted: `<meta name="robots">`, OpenGraph (`og:type` `product`/`article`/`website`, `og:image` 1200×630, `og:locale` `en_IN`), Twitter card `summary_large_image`, `product:price:amount`/`currency` meta for PDP, `alternate` hreflang omitted in v1 (single locale), `theme-color`, favicons/manifest.

Default OG images are generated per entity with `opengraph-image.tsx` (product image on brand background) so every shared link looks premium.

### 1.4 Structured data (JSON-LD)

All generated server-side from the database by `modules/seo/structured-data.ts`, validated in unit tests against the schema.org vocabulary and in CI against Google's Rich Results test on preview URLs for sample pages.

| Page | Types |
|---|---|
| All pages | `Organization` (site-wide in layout: name, URL, logo, `sameAs` socials, `contactPoint`), `WebSite` with `SearchAction` (home only) |
| All except home | `BreadcrumbList` |
| PDP (single variant) | `Product` with `name, image[], description, sku, brand, material, color, category, aggregateRating?, review[] (approved, latest 5)`, `offers: Offer { price, priceCurrency: INR, availability, itemCondition: NewCondition, url, priceValidUntil (sale end), shippingDetails: OfferShippingDetails, hasMerchantReturnPolicy: MerchantReturnPolicy }` |
| PDP (size/length variants) | `ProductGroup` with `hasVariant: Product[]` each with own sku/offer/size, `variesBy`, plus `productGroupID`; colour/finish siblings are separate products linked via a family `ProductGroup` `@id` (§1.10) |
| Category / collection PLP | `CollectionPage` + `ItemList` of product URLs (positions), no per-item offers (avoids rich-result spam) |
| Journal | `Article` (headline, image, datePublished, dateModified, author `Person` with name and author page URL, publisher `Organization`) |
| Guides | `Article` + `FAQPage` when FAQ block present; `ItemList` for product sets |
| FAQ page | `FAQPage` |
| About | `AboutPage` + `Organization` |
| Contact | `ContactPage` |
| Policies | `WebPage` (returns page additionally hosts the canonical `MerchantReturnPolicy` node referenced by `@id`) |

`MerchantReturnPolicy` and `OfferShippingDetails` are built from `settings` (return window days, return method, fees, shipping rates by `DefinedRegion` IN, handling/transit time) and referenced by `@id` from each Offer to avoid duplication.

### 1.5 Sitemaps and robots

- `/sitemap.xml` index → `/sitemap/products-{n}.xml` (≤ 5,000 URLs each), `categories.xml`, `collections.xml`, `journal.xml`, `guides.xml`, `pages.xml`. Includes `lastmod`; products include image sitemap entries (`image:image` with `image:title`). Video entries for PDPs with hosted video.
- Only `status=active`, `noindex=false` entities. Archived products drop out immediately.
- `/robots.txt`: allow all; disallow `/cart/`, `/checkout/`, `/account/`, `/admin/`, `/api/`, `/search/`, `/wishlist/`, `/track-order/`; `Sitemap:` line. Parameterised URLs (`?sort=`, `?variant=`, facets) are **not** blocked in robots, because a robots block would stop Google from reading their `noindex`/canonical directives; crawl waste is controlled with `nofollow` on those links instead. Preview deployments serve `Disallow: /` and `X-Robots-Tag: noindex`.
- Sitemap submitted to Google Search Console and Bing Webmaster Tools; GSC property verified via DNS.

### 1.6 Redirects, 404, 410

Per `04_INFORMATION_ARCHITECTURE.md §7`. Redirect lookup runs in the request proxy using a cached map (invalidated on admin change). Hit counts are recorded asynchronously (outbox) so redirects stay fast.

### 1.7 Pagination and faceted navigation control

- Facet parameters whitelisted and ordered deterministically (`?material=…&color=…&price=…`) so the same selection always yields the same URL.
- Unknown or invalid parameter values → 404 (not an empty 200 page).
- Facet links are real `<a href>` but carry `rel="nofollow"` when they would create non-canonical URLs; crawl budget is preserved while users get normal links.
- Max 2 simultaneous filter dimensions linked from HTML; deeper combinations are reachable only via user interaction.

#### 1.7.1 Implementation (built 2026-10-05)

The faceted strategy is enforced in code, not by convention:

| Rule | Where |
|---|---|
| Facet keys and values are whitelisted from attribute definitions, price buckets and availability; anything else returns **404** | `src/modules/catalog/facets.ts` → `parseListingSearchParams`, used by `src/components/catalog/listing-route.ts` |
| Tracking parameters (`utm_*`, `gclid`, `fbclid`, …) are tolerated and dropped from the canonical | same |
| One state, one URL: fixed key order, sorted comma-joined values, `page=1` and default sort omitted; `?page=1` → 301 | `buildListingHref`, `resolveListing` |
| Indexable only when unfiltered and unsorted; otherwise `noindex, follow` + self-canonical; paginated pages indexable with "– Page N" titles | `src/modules/seo/metadata.ts` → `listingMetadata` |
| Facet controls are form checkboxes, not links; the only facet links in HTML (active-filter chips) carry `rel="nofollow"` | `src/components/catalog/filter-form.tsx`, `active-filters.tsx` |
| Page beyond the last → 404; category depth > 1 → 404 | `listing-route.ts`, `gender-route.tsx` |
| Sitemap lists categories, collections with ≥ 3 products and active products only, never a query string | `src/app/sitemap.ts` |
| PLP structured data: `BreadcrumbList`, `CollectionPage` + `ItemList`, `FAQPage` when FAQ exists | `listing-page.tsx`, `structured-data.ts` |
| PDP structured data: `Product` (single variant) or `ProductGroup` with per-size `Offer`s; ratings omitted until they come from verified reviews | `products/[slug]/page.tsx` |

Unit tests in `tests/unit/facets.test.ts` and `tests/unit/listing.test.ts` pin these rules.

### 1.8 Image SEO

- Descriptive filenames generated from product slug + role (`pearl-drop-earrings-gold-plated-01.jpg`) on upload.
- `alt` mandatory in admin (validated); pattern suggested: `{product name} in {finish} on model` / `… flat lay`.
- `next/image` with explicit `width/height` (no CLS), AVIF/WebP, `priority` for LCP image, `loading="lazy"` otherwise.
- Image sitemap entries; OG images 1200×630.

### 1.9 International/locale

`lang="en-IN"`, `og:locale en_IN`, INR pricing, IST dates. No hreflang in v1.

### 1.10 Variants versus sibling products (review finding, ADR-29)

Jewellery is searched by finish and colour ("silver pearl drop earrings", "rose gold chain for men"). If every finish is a variant on one URL, those queries have no page to rank and `ProductGroup` markup alone will not win them.

Rule:
- **Variants** (`?variant=`, same URL) are used only for options that do not change what the item *is*: ring size, chain/bracelet length, quantity packs.
- **Colour and finish** are modelled as **separate products** that share a `product_family_id`. Each has its own slug, images, copy, reviews and canonical URL. The PDP shows a "Also available in" swatch row linking the siblings (server-rendered `<a>` links), and `Product` schema uses `isSimilarTo` / `isVariantOf` pointing to a family `ProductGroup` node.
- Admin creates a family once and "duplicates as sibling", so entry cost is low; the feed uses `item_group_id = family_id`.
- Exception: trivial colour options with no search demand (e.g. thread colour on a rakhi) may remain variants at the admin's discretion.

This is cheap to adopt now and very expensive to retrofit (URL changes, review migration, redirect sprawl) later.

### 1.11 Media URLs on our own domain (review finding, ADR-30)

Product images are served from `https://{domain}/media/{path}` via a rewrite to storage, and optimised images from `/_next/image`. Image sitemaps, `og:image`, feed `image_link` and schema `image` all use the `/media/` URL. Storage can move vendors without changing a single indexed image URL.

## 2. Content SEO architecture

### 2.1 Keyword-to-page mapping

| Intent | Example queries | Page type |
|---|---|---|
| Category / commercial | "earrings for women online", "men's chains" | Category PLP with intro copy, FAQ block, sibling links |
| Occasion / commercial | "wedding jewellery set", "party wear earrings", "office wear jewellery" | Collection with editorial header and curated products |
| Material / commercial | "anti tarnish jewellery", "gold plated necklace", "oxidised earrings" | Collection (rule-based on attribute) |
| Price | "earrings under 500", "jewellery under 999" | Rule-based collection; copy explains the edit |
| Style intent / informational-commercial | "jewellery for saree", "jewellery for kurti", "earrings for round face" | **Style guide** (real guidance + shoppable modules) |
| Gifting | "jewellery gifts for women", "anniversary gift for wife jewellery" | **Gift guide** |
| Informational | "how to clean gold plated jewellery", "difference between gold plated and gold toned" | **Journal** / care guide |
| Brand | "kesa lifestyle", "kesa jewellery" | Home, About |

Each keyword cluster maps to **exactly one** primary page to prevent cannibalisation. Admin SEO panel shows the "focus keywords" field so editors can see clashes (P1: cannibalisation report).

**Collection vs guide split (review finding).** The same topic can tempt both a collection and a style/gift guide (e.g. "party wear jewellery"). The rule:

| Page | Owns | Title shape | Example |
|---|---|---|---|
| Collection | the commercial head term | `{Head term} \| Kesa` | `/collections/party-wear-jewellery/` → "Party Wear Jewellery" |
| Style/gift guide | the advisory long-tail ("what to wear", "how to choose", "with a saree") | `What Jewellery to Wear {context}` / `How to Choose …` | `/style-guides/jewellery-for-party-wear/` → "What Jewellery to Wear to a Party: A Styling Guide" |

Guides link prominently to their commercial collection; collections link to the guide in the body copy. The focus-keyword field is unique across entities (enforced in admin) so two pages can never target the same head term. Price-band topics are owned by **collections only** (no "under ₹999" gift guide; the gifting guide links to the collection).

### 2.2 Style-intent landing pages (useful, not doorway)

A style guide qualifies for publication only if it has:

1. ≥ 600 words of original guidance written for the reader (how to choose, what to pair, common mistakes).
2. ≥ 2 editorial images (lifestyle/lookbook).
3. ≥ 2 product modules with curated products (not the same generic bestseller block everywhere).
4. ≥ 3 FAQs specific to the topic.
5. Internal links to ≥ 2 categories/collections and ≥ 1 related guide/article.
6. A named author and a last-updated date.

Pages failing the checklist stay in draft; the admin shows the checklist as a publishing gate.

Launch set (Phase 3):
- `/style-guides/jewellery-for-saree/`
- `/style-guides/jewellery-for-kurti/`
- `/style-guides/wedding-guest-jewellery/`
- `/style-guides/jewellery-for-office-wear/`
- `/style-guides/jewellery-for-party-wear/`
- `/style-guides/earrings-for-your-face-shape/`
- `/gift-guides/jewellery-gifts-for-women/`
- `/gift-guides/anniversary-jewellery-gifts/`

(Price-band pages such as "under ₹999" are collections, per the split rule in §2.1.)

### 2.3 Category and collection copy

- Intro (above grid): 60–120 words, customer-facing, answers "what will I find here".
- Body (below grid): 200–400 words with sub-headings (how to choose, styling, care), 3–5 FAQs. Collapsible on mobile but present in HTML.
- Written per page by a human; the admin flags duplicates (P1: similarity check).

### 2.4 Product copy

- Short description: benefit-led, ≤ 160 chars.
- Description: 80–200 words, unique per product (no marketplace copy-paste). Template prompts in admin: *what it is, what it pairs with, material and finish, how it feels, care*.
- Specs table filled from attributes (also improves `Product` schema).

### 2.5 Journal

Cadence 2–4 posts/month (D13). Pillars: styling, care, gifting, trends, behind-the-brand. Every post links to products via modules and is linked back from relevant categories ("From the Journal").

### 2.6 Internal linking

Rules in `04_INFORMATION_ARCHITECTURE.md §8`, implemented through required fields and automatic modules, not editorial discipline alone.

### 2.7 E-E-A-T signals

About page with real people and workshop/QC process; author names on guides; verified-purchase reviews; clear policies; grievance officer; physical address; consistent NAP across Google Business Profile and socials.

## 3. Reviews and ratings SEO

- Only approved, verified-purchase reviews feed `aggregateRating`; rating shown on PDP in HTML.
- Review request email sent 7 days after delivery (outbox job) with one-click star entry to maximise volume.
- Reviews paginated on PDP with first 5 in HTML, rest loaded on demand (no separate indexable review URLs).

---

## 4. Google Merchant Center and product feed

- Feed route `/api/feeds/google-merchant` (protected by a long random token in the URL, rotated via settings) producing RSS 2.0 / XML with Google Shopping namespace: `id` (variant SKU), `item_group_id` (product), `title`, `description`, `link`, `image_link`, `additional_image_link`, `availability`, `price`, `sale_price` + `sale_price_effective_date`, `brand`, `gtin` (if any), `mpn` (SKU), `condition`, `google_product_category` (Apparel & Accessories > Jewelry > …), `product_type`, `gender`, `age_group`, `color`, `material`, `size`, `shipping` (IN), `tax` not required for IN, `identifier_exists`.
- Regenerated hourly by cron into a cached file; Merchant Center scheduled fetch.
- Prices/availability on the landing page must match the feed → the same `variant_prices` view powers both.
- Free listings enabled; structured data on PDP makes automatic item updates possible.
- Return and shipping settings configured in Merchant Center to match `MerchantReturnPolicy`.

---

## 5. Google Search Console and monitoring

- GSC property on the chosen host; sitemap submitted; email alerts to the owner.
- Weekly checks (manual at first, later a cron summary): coverage errors, Core Web Vitals report, rich result errors, manual actions.
- Admin dashboard (P1) pulls GSC API for top queries/pages per category.
- Change log of SEO-affecting deploys kept in the ADR appendix.

---

## 6. Launch SEO checklist

1. Host, HTTPS, redirects (www/apex, http→https, trailing slash) verified.
2. `robots.txt` allows crawling; preview `noindex` removed from production.
3. Sitemaps valid and submitted.
4. Structured data passes Rich Results test on home, PLP, PDP (single + variant), article, guide, FAQ.
5. Canonicals correct on filtered/paginated PLPs.
6. 404 and 410 return proper status codes.
7. All category/collection pages have intro + body copy.
8. Every product has unique description, alt text, primary image.
9. Merchant Center feed accepted with zero disapprovals on a sample.
10. GA4 + GSC + Merchant Center linked.
